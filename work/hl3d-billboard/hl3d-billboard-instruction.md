# 指示：3D観戦の選手を「2Dの絵の板（ビルボード）」に替える

対象リポジトリ：`shroudf-wq/pennant-race-v2-dev`（正本 `src/pennant_source.html`、v2.2.l／BASE_V1 v1.8.b）

始める前に、このリポジトリの `CLAUDE.md` と `docs/引き継ぎ書_v2.md` の0章・4.6〜4.8・5章を読んで、その決まり通りに作業すること。特に「計算部は v1 が正・v2で触るのは絵の部分だけ」「セーブ形式は変えない」「`src/pennant_source.html` を直接書き換えてコミットしない（パッチ方式）」「APP_VERSION は変えない」は厳守。

## なぜやるか（実測した問題）

3D観戦を実際に描画して確認した結果、機能は正常（エラーなし・テスト通過）だが、見た目が「しっくり来ない」。原因は球場側ではなく選手側にある。

- 選手（`hl3dMan`）は胴＝円筒（半径2.1／2.5・高さ6）、頭＝球（半径2.2）、腕＝円筒2本で、**脚がない**。顔も単色の球で、似顔絵の要素が一切入らない
- 幅390pxの観戦画面では、選手は帽子の色がうっすら分かる程度の小さな駒にしか見えず、名前の札の方がはるかに大きい。3D化で一番増えてほしい「選手の存在感」が一番薄い
- 試合画面の背景（`hl3dBgBuild`）の選手も、小さな瓶型の人形に見える

球場（スタンド・観客・屋根・ビジョン）の作り込みは十分なので、そこは残し、選手だけを2Dの絵に替えて、絵柄の個性と存在感を取り戻すのが目的。

## やること

### 1. 選手をビルボードの絵に替える（観戦側が必須）

- 対象は観戦3D（`hl3dStart0` が立てる `items` の `man`）。`hl3dMan` の代わりに、Canvasに描いた人の絵を貼った板（平面）を使う
- 板は足元を支点にして地面に立て、横方向（Y軸）はカメラを向く。上下は**カメラの見下ろしの7割だけ**カメラのほうへ倒す（横だけだとバックネット裏のカメラ＝見下ろし51°で絵が半分の高さに潰れる。見本 `proto_hl3d_billboard.py` の `hl3dBillFace` と同じ）
- 足元の丸い影（現行の `shadow` の円）と、打者＝赤・走者＝黄の役割リングは、今のものをそのまま残す
- **名前の札（`.hl3tag`）は 3D では出さない**（絵の板と重なって見づらいだけになる。決定済み）。得点の +N・三振の K・アウトの印・名前の帯（上端の1行）は今のまま。札を消すぶん、`hl3Declutter`（札の重なりをほどく処理）は 3D では札がない前提で動いてよい（エラーにならないこと）
- 板はいつもカメラ側を向くので、「走る向きを向く」「投げる向きを向く」（`rotation.y`）は使えない。代わりに、向きがカメラから見て左向きのときは絵を左右反転（`scale.x=−1`）する
- 透明部分の重なりで描画順が崩れないよう、透明の扱い（alphaTest 等）には注意する

### 2. 人の絵の描き方

- 絵は Canvas 2D でその場で描いて texture にする。外部の画像ファイルは足さない
- 姿は **2.5頭身くらいのデフォルメ** で、少なくとも次が読み取れること：脚2本（ズボンと靴）、胴（ユニフォーム）、腕2本、頭（顔に目・眉・口の最小限のパーツ、肌色は現行の `hl3dUniform` の skin を使う）、帽子とつば
- 色と柄は新しい決め方を作らず、現行の `hl3dUniform`（ホーム／ビジターの色分け、縦縞・胸の帯の texture、球団名ハッシュの型）をそのまま流用する
- 野手にはグラブ、打者にはバットを持たせる（現行の3Dの打者にはバットがないので、ここは改善点として入れる）
- texture は選手ごとに作り直さず、ユニフォームの型×役割×姿勢の組み合わせで使い回す（現行の `hl3dUniTexC` と同じ考え方）

### 3. 姿勢は3種類＋走りの2コマ

- 用意する姿勢：①立つ（守備位置・通常）②投げる／捕る ③走る（脚の前後を入れ替えた2コマ）④しゃがむ（捕手・ベンチ）
- 切り替えのタイミングは新しい仕組みを作らず、既存の台本・キーフレーム（`kf`／`poses`／`hl3dArm` が決めている時刻と向き）をそのまま使う。**位置・時刻・結果のデータには一切触らない**
- 走っている間は移動の位相で2コマを交互に出す

### 4. 背景側の選手と、球場にいる選手も全部この形に（必須）

- 試合画面の背景（`hl3dBgBuild` の `men`・捕手）も同じ部品で替える（毎コマ `hl3dBgDraw` でカメラのほうを向ける）
- `hl3dParkMeshes` の中で `hl3dMan` を使っている所も全部：ブルペンの投手・捕手（ファウルゾーン型・フェンス裏型）、ベンチに座る選手、ネクストバッターズサークルの打者、背景の捕手。しゃがむ捕手・座る選手は「しゃがむ」の姿勢（脚を短く）を1つ足して使う。ベンチの選手は屋根（高さ4.6）に頭が刺さらない大きさに（見本では scale .6・床 −2.4）
- 観戦の 3D でも、ベンチなど球場の人の板は毎コマカメラのほうを向ける（`hl3dUpdate` で。見本の `S.bills`）
- 置き換えたあと、`hl3dMan` を使う所が残っていないこと（`grep -n "hl3dMan(" ` で確かめる）

## やらないこと

- 球場・地面・フェンス・観客・ビジョンには触らない（選手の比較をきれいに取るため、今回は分ける）
- カメラの位置・画角（`HL3D_CAMS`）は変えない
- 試合の計算、乱数、セーブ、2.5Dの絵には触らない。Three.js が読めないときに 2.5D に落ちる動きも現行のまま
- 3Dまわりで物を作る・描く所は、決まり通り `hl3dNR(()=>…)` で包み、演出の乱数を試合の乱数と混ぜない

## 確かめること（テスト）

1. パッチを当てた出力に `node --check`（script 部分）を通す
2. `tests_v2xx/hl3d_shots.py`（`HL3D_LOCAL=vendor/three-0.128.0.min.js`）を幅390と幅1366で回し、前（プレー前）・プレー中の写しを撮る。エラーなし・札のはみ出しなしを確認し、**変更前と変更後の写しを並べる**
3. 選手の見え方を数字で測って README に書く：幅390のプレー前で、選手1人の画面上の高さ（px）が変更前と比べてどうなったか
4. `tests_v2xx/par_v2.py` で、同じ乱数で v1（BASE_V1＝v1.8.b）と結果が1つも違わないことを確かめる。v1側のファイルがこの作業場所にない場合は、無理にやらず「未実施」と理由を README に書く（やったことにしない）
5. 背景側を替えた場合は `tests_v2xx/hl3d_bg.py` も回す
6. 重さの確認：観戦1場面の draw call 数と、撮影テストの実行時間の変化を README に書く
