# v1 → v2 の同期手順(計算部を流す)

v2 の計算部(試合・成長・ドラフト・FA・殿堂入りなど結果を決める部分)は v1 が正。v1 で版を上げたら、その差分を v2 にも流す。道具は、v1 の差分の形によって2通り(下の「A」「B」)。

## 最初の1回(v2.0.a を作るとき)

1. v1 の正本(`claude/pennant_source.html`、v1.1.x)を複製して v2 の出発点にする。
2. `const APP_VERSION="v1.1.x"` を `const APP_VERSION="v2.0.a"; const BASE_V1="v1.1.x";` にする(`BASE_V1` が「元にした v1 の版」。同期のたびに上がる)。
3. 題字・設定の「バージョン」表示など、版を出している所に `BASE_V1` も添える(例:`v2.0.a(2D: v1.1.x)`)。不具合の報告で「どの v1 の計算か」が分かる。
4. v1 のテスト `par_x.py` を写して `tests_v2xx/par_v2.py` にし、**同じ乱数で v1.1.x と v2.0.a の結果が一致**することを確かめる(複製しただけなので一致するはず。ここが出発点)。

## v1 が上がるたび

### A. v1 の差分が `rep(old,new)` の patch(`tests_v11y/patch_v11y.py`)のとき

```
python3 sync_v1_to_v2.py  <v2の今の正本>  <v1のtests_v11y/patch_v11y.py>  <出力>  --v2 v2.0.c  --base v1.1.y
```

- 当たらない rep があると止まる。止まったら、v2 でその部分に触っていないかを見る。**計算部に触っていたのが原因なら v2 側を v1 の形に戻す**(触ってよいのは絵の部分だけ)。絵の部分と重なっていたときだけ手で合わせる。
- `APP_VERSION` の rep は飛ばされる(v2 の版は `--v2` で付ける)。
- v1 の patch が**絵の部分**(観戦の演出・設定の欄)も直している版は、当てる前に中身を読む。v2 は絵を作り直しているので、その rep は当たらないか、当たっても意味が違うことがある。そのときは絵の部分の rep を patch から外して当て、v2 の絵に合うように手で入れる。
- 複数の版を飛ばしたときは、**v1 の版の順に1つずつ**当てる(v1.1.y → v1.1.z)。順を飛ばすと途中の rep の `old` が見つからない。

### B. v1 の差分が unified diff(`v1.1.y_to_v1.2.k.patch` のような、何版かをまとめたもの)のとき(v2.0.e で初めて使った)

`patch` で v2 に直接当てると、v2 が書き換えた絵の部分で文脈がずれる。**3者マージ**で合わせる(元 = 前に元にした v1、こちら = v2 の今の正本、あちら = 新しい v1)。

1. 差分が本物か確かめる:元の v1(例 v1.1.y)の複製に `patch -p1` で当て、新しい v1 の本編と1バイトも違わないこと(説明の .md の SHA256 とも照らす)。
2. `git merge-file -p --diff3 -L v2 -L 元v1 -L 新v1 <v2> <元v1> <新v1>` で合わせる。両方が同じ行を変えた所だけが衝突(`<<<<<<<`)になる。
3. 衝突を解く。決まり:**v2 の絵の層(2.5D の `hl3*`・設定の「立体」)はそのまま残し、v1 の変更も全部入れる**。版の行は `APP_VERSION="v2.0.x"; BASE_V1="新v1"` にする。
4. 衝突しなかった所の見落としを探す:新 v1 が観戦の描画の関数(`hlRenderPlay`・`hlRenderPre`・`renderManaged`・`hlSceneInner` など)の **2D の道にだけ**足したもの(SVG の `inner` や重ね `over` に足したもの)は、v2 の 2.5D の道では素通りになる。元v1 と新v1 の関数ごとの差を見て、2.5D の道にも入れる。
5. 1〜4 をスクリプトにして残す(例:`tests_v2xx/sync_v12k_v20e.py`・`sync_v12v_v20k.py`。衝突の数が想定と違えば止まる)。同じ入力なら同じ結果になる。
6. 新しい v1 が**記録に項目を足した**とき(例:v1.2.v の場面の打球 `ev.bp`・作戦 `ev.tac`・ゴロの間の得点 `ev.gg`、球団の球場の屋根 `t.park.dome`)は、v2 の 2.5D の層がそれを読むように直す(同期のスクリプトの rep に入れる)。v2 の層が自分で決めていたもの(打球の向き・屋根)は、記録があれば記録を優先し、ないとき(前のセーブ・設定なしのリーグ)はこれまでどおりにする。
7. v1 のテストの道具(`h.py` など)が変わっていたら、v2 の `tests_v2xx/` の同じものも合わせる(v1.2.m でリーグ作成の欄が折りたたみに入り、`create()` が折りたたみを開くようになった。v1.2.w で `SEASON` が銀河杯・世界大会を自動で進めるようになった)。
8. 新しい v1 が**観戦・采配に入る新しい試合**を足したとき(例:v1.2.w の銀河杯・v1.2.y の世界大会)は、その試合を v2 の 2.5D・3D で観戦・采配して最後まで描けるかを確かめる(`hl3_cup.py`)。ホームが球団でない(代表チーム)と、球団の色・球場の個性はないので v2 の層の決めた形(灰色の帯・ふつうの球場)になる。

**差分のファイルがないとき**(v2.0.k で初めて):v1 の版ごとの差分は `filesb\v1.x.y\tests_v1xy.zip` の中の `patch_v1xy.py`(rep の並び)にあるが、何版も飛ばしたときは、元の v1 と新しい v1 の**本編**(`filesb\v1.x.y\pennant_source.html`)をそのまま 2 の「元」「あちら」にして3者マージしてよい。1 の代わりに、元の v1 の本編が前回の同期で使ったものと1バイトも違わないことを確かめる。各版の `README_v1xy.md` を読んで、絵の部分・記録に足された項目を拾う(6)。

## 当てたあとの確認(必ず)

1. `par_v2.py`:同じ乱数で、v2 の結果が **v1 の同じ版**(BASE_V1)と一致する。スキルあり・なし・アメリカ式。比べる v1 は**新しい v1**にする。
2. `sav_v2.py`:互換テスト用のセーブ(`tests_v2xx/saves/`。PC では `filesb\v2\saves_v1.1.y\`)を新しい v1 と v2 で読み、①〜④(残りのシーズンが一致・観戦が最後まで・v2 の保存を v1 が読める)。
3. 観戦・采配を 2.5D(あり/弱)/ 2D / アニメーションオフ で最後まで進める。新しい v1 が観戦の画面に足した表示(例:v1.2.k のボールカウント)が 2.5D の札と重ならないか、`hl3_overlap.py` で数える(**1つずつ回す**。いくつも同時に回すと時間がずれて数が変わる)。`hl3_manage.py`(采配の各場面が新しい v1 と一致)・`hl3_throw.py`(送球とアウトの順番)も。
4. 引き継ぎ書の「元にした v1」と版ごとの記録を上げる。

## v1 の patch が同期しやすいように(v1 側の約束)

- patch は `rep(old,new)` の並びで書く(今のまま)。`old` は計算部の中でそのまま一意に当たる長さにする。何版かまとめて unified diff にするときは、元の版・先の版の SHA256 と、含む版の一覧を説明に書く(v1.2.k のときと同じ)。
- 版を上げるだけの rep(`APP_VERSION`)は、最初の1行にまとめる(今のまま)。
- 絵の部分と計算部を1つの rep で一緒に直さない(分けておくと v2 で片方だけ当てられる)。
- 計算部に**新しい記録の項目**を足すとき(例:打球の方向を試合の記録に残す)は、v1 で足して v2 に流す。v2 で先に足さない。

## v2 で計算部を直したくなったら

直さない。v1 の不足点の表に書いて v1 で直し、同期で受け取る。v1 と v2 の計算が食い違うと、「同じ乱数で一致」の確認が効かなくなり、3D の不具合と計算の不具合が切り分けられなくなる。
