## 2. 版の付け方

- `v2.0.a` → `v2.0.b` … と、v1 と同じ字送り。2.5D が一段落して Three.js に移るときに `v2.1.a`。
- v1 を同期した版も、版を1つ上げる(引き継ぎ書の版ごとの記録に「v1.x.y を同期」と書く)。
- v2 で変えた所は `tests_v2xx/patch_v20x.py` の `rep(old,new)` の並びで残す(v1 と同じ約束)。v1 を同期したときは、その手順をスクリプトにして残す(`sync_v12k_v20e.py`)。v1 の差分を流すとき、どこが v2 で変わっているかをこれらで確かめる。

## 3. 容量の決まり(v1 と同じ)

1. ソースは `claude/pennant_source.html` の1つだけ
2. 引き継ぎ書・更新履歴は1つだけを上書き
3. テストは今の版と1つ前の版のぶんだけ残す。古いものは PC の filesb に控えてから消す
4. 保存の前後に project_info で容量を確かめ、1.5MB を超えたら案を出してから進める
5. 消す前に PC に控えを取り、元と同じか確かめる
6. 控えや古い版は PC の `filesb\v2\版の名前\` に置く
7. セーブデータ(1本 2〜4.5MB)・試作のページ・画面写し・v1 の差分・公開用の写しはプロジェクトに置かない。PC の `filesb\` に置き、要るときに取り寄せる

## 4. 作りの方針(v1 との違いはここだけ)

- 変えてよいのは**記録を読んで絵にする部分**だけ:ハイライト観戦(回の札・プレー前・プレー)、じっくり采配の演出、観戦の設定の欄。v2.1.j から、試合画面の背景も(決め事 10)。
- 「記録 → 動き(軌道・走者の移動)」の層を1つ作り、2.5D と Three.js の両方がその層を読む。絵の作り方だけが違う。
- 演出に使う乱数は、試合の乱数と**別の種**を使う(音と同じ)。試合の乱数に触ると結果がずれる。
- 今の記録が「左安・中本・併殺」のような結果の種類までなら、方向・角度・飛距離は結果から決めて作る(計算部に項目を足さない。足したくなったら v1 側に足して同期する)。
- 絵の側から、球団や選手に値を書き込む v1 の関数(例:`parkOf()` は球団に `park` を書き込む)を呼ばない。v1 の計算がすでに書き込んだ値を読むだけにする(決め事3)。
- 観戦の枠の比(300:230)と、設定の演出項目(強弱・つなぎ・プレー前・流れの帯・速さ・ボールカウント)は 3D でも守る。アニメーションをオフにしたら結果だけ出す。
- Three.js は cdnjs から読む。読めないときは 2.5D に自動で戻す。人型は使わず、カプセル形・低ポリ・立て札で済ませる。

### 4.1 2.5D のカメラ(v2.0.b で実装。値は `HL3_CAMS`)

作り:今の `hlFieldSvg`(300×230、本塁 150,212)を地面として1枚だけ `perspective`+`rotateX`+`rotateZ` で回す(`.hl3cam` > `.hl3world`)。野手・打者・走者はカプセル形+立て札(`.hl3bb`)で、地面の点に立ててカメラの逆回転 `rotateZ(-φ) rotateX(-θ)` で正面を向かせる。ボールは地面の影(`.hl3sh`)+高さぶんの `translateZ`(Web Animations API で本塁→落点の線の上を飛ぶ)。走者は塁の線を滑る(時間は 2D の `hlMovingRunners` と同じ)。軌跡の線・本塁打の光・投手交代の脈は SVG の地面に描いたまま。ライブラリなし。

### 4.4 送球とアウトの順番(v2.0.j。`hl3Fielding`・`hl3OutMarks`)

- どこへ投げるか(結果から決める。試合の記録に送球の塁はない):
  - ゴロの凡打:捕った野手 → 一塁。併殺:→ 二塁(一塁走者)→ 一塁(打者)
  - 送りバント:転がった所 → 一塁。野選(v1 ではバントの失敗だけ):→ 二塁走者がいれば三塁、いなければ二塁(先の走者を封殺)
  - フライの凡打:投げない。捕った所に「アウト」
  - 安打で走者が刺される(記録でアウトが増えた安打。刺されたのは塁の動きがない走者):単打の二塁走者・長打の一塁走者 → 本塁、単打の一塁走者 → 三塁
- 時刻(打ってから。秒):打球が着くのは 0.9 秒。ゴロ・バントは 0.08 秒、外野は 0.3 秒で投げる。送球の時間は 0.1+距離÷650。併殺の中継は 0.06 秒。走者は 0.9 秒に走り出し、1つの塁に 0.32 秒(`HL_PER`)
- アウトになる走者:ボールが塁に届いた 0.05 秒あと(遅い走者はそのぶん速さを合わせる)に着き、「アウト」の印。印は 1.5 秒で出て消える(札に重ねたままにしない)。走者は 0.45 秒後に消える
- アウトと得点の順番(野球の決まり):
  - 3つ目のアウトが**タッチプレー**(三塁・本塁で刺す)で点が入る場面:得点の走者が本塁を踏んだ 0.12 秒あとにアウトの印(送球を待たせる)。踏む前のアウトなら、その点は入らないため
  - 3つ目のアウトが**フォースアウト**(打者の一塁・封殺)で点が入る組み合わせは、計算では出ない。出たときは本塁を踏むのをアウトのあとにする(`arr`)
- 打球:采配の結果では、v1 の計算が直前に決めた打球 `lastBIP`(ゴロ/フライと処理した野手)を**読むだけ**で使う(凡打・エラー)。観戦(見返し)には打球の記録がないので `hlRand` で決める。記録の場面(`ev`)には何も書き込まない(見返しの記録はセーブに入るため)
- 観戦では、アウトの数・点数を変えるのを最後のアウトのあと(`fld.end`)まで待つ
- 2D の図は v1 のまま(送球なし)
- v1.2.v の作戦と走塁(v2.0.k):ゴロゴーは v1.2.v で v1 に入った(v1.2.k にはなかった)。凡打の守備は、記録の「打つ前の塁 `pn`・動いた走者 `mv`・打った後の塁 `af`・増えたアウト」から決める(記録に誰がどこでアウトかはないため):
  - 動いていない走者のうち、打った後にその塁が空いた人がアウト。ゴロなら次の塁で(一塁走者=二塁で封殺・三塁走者=本塁でアウト)、フライ・ライナーなら元の塁で(飛び出して併殺。走者は動かずに消える)
  - 打者は、どこかへ動いていなければ、ゴロなら一塁でアウト・フライなら捕られてアウト
  - 送球の順は先の走者から、最後に打者(併殺は二塁→一塁)。ゴロの間に還る三塁走者は `mv` の [3,4] で走り、打者は一塁でアウト
  - この数が増えたアウトと合わないとき(記録が足りない)は、v2.0.j と同じく打者だけ一塁でアウト
  - 作戦と走塁で点が入る凡打は、どれも2アウト未満で起きる(3つ目のアウトにならない)ので、順番の決まりは今のところ安打で刺す場面だけに効く

- 札が描かれない不具合(v2.0.k で直した。v2.0.b から):走者を消す動き(本塁に還った・アウトになった)を、遅らせて先に作っていた。待っている間の不透明度の動きで 3D の重なりが崩れ、その走者の札がまったく描かれなかった(本塁へ走る走者・アウトになる走者)。消す時刻になってから作るようにした。あわせて、札の重なりをほどく1回目に、走る前の走者も入れた(三塁走者が三塁手の札の下に隠れたままにならないように)

- **姿勢** `hl3dBillPoseOf(S,it,t,dv)`:台本の捕る・投げる(`it.poses`。`hl3dArm` と同じ時刻)と飛びつき → throw、走る速さ 8 以上 → run1/run2(移動の位相 `it.ph`)、捕手は打つ前 → crouch。`hl3dBillPose(m,pose)` で絵を差し替える。**位置・時刻・結果は台本のまま**(`bb_check.py` ④:位置と腕の角度が v2.2.l と1つも違わない)
- **札**:3D では名前の札(`.hl3tag`)を出さない(板と重なるだけ)。最後まで作れたときだけ `.hl3dLab` から外す(途中で失敗したら 2.5D に札ごと戻る)。`hl3Declutter` は札のない人を飛ばす。2.5D(立体あり)は札そのまま
- **顔の書き分け**(v2.2.n ⑥。ユーザー「3 は書き分けで」):`hl3dFace(seed)`=`forteHash(名前+"顔")>>>3 % 360`。髪の色 3(`HL3D_HAIR`)・髪の長さ 2・ひげ 3(なし/口ひげ/あごひげ)・目 2(丸/細い)・眉 2(細/太)・肌 5(`HL3D_SKIN`。v1 の `BCF_SKIN` と同じ 5 色)=360 通り(`hl3dFaceOf(f)`)。観戦は札の `data-nm`(名前の全体。`hl3TagHtml` に足した。`it.nm` に控える)から、背景・ベンチ・ブルペン・待つ打者は置き場の名前(「背景一」「ベンチ1 0」など)から決める。乱数もセーブも使わない。同じ名前は同じ顔(似顔 `FACE` とは別の決め方。`p.faceSeed` は読まない)
